# Phase 4 Report 15 - Raw Video Preview In Retrieval UI

## Scope

- Added a raw video preview flow for L21 videos that are registered with `video_path`.
- Retrieval results now include `video_url` when the corresponding raw `.mp4` exists in the registry.
- The browser UI shows an `Open video` action only when a result has raw video available.
- The modal video player seeks near the result timestamp when `pts_time` is available.

## Implementation

- Backend:
  - Added `RetrievalUiService.video_url(video_id)`.
  - Added `RetrievalUiService.resolve_video_path(video_id)` with repository boundary checks.
  - Added `/video?video_id=...` route.
  - Added byte range support for streamed video responses so browsers can seek without downloading the whole file.
- UI:
  - Added an `Open video` button to result cards.
  - Added a native dialog with an HTML5 `<video>` player.
  - Added close/reset behavior so playback stops when the dialog is closed.
- Tests:
  - Covered `video_url` enrichment.
  - Covered safe video path resolution.
  - Covered metadata search returning `video_url`.
  - Covered static UI wiring for the preview dialog and JS flow.

## Notes

- This does not process video content yet; it only previews raw registered videos.
- The feature depends on `video_path` being present in `artifacts/registry/data_registry.json`.
- It should continue to work for future groups after their raw videos are added and the registry/index are rebuilt.
