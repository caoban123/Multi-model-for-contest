## HTTP Response Repair

Observed exception:

```text
OSError: [Errno 22] Invalid argument
at self.wfile.write(...)
```

This normally occurs when the browser cancels an image request while the threaded server is still writing it. The initial fix caught every `OSError` around file open, read and socket write. That suppressed the traceback but also hid real E-drive read failures. It also accidentally removed `_handle_translate` while `/api/translate` still called it.

Final behavior:

- `_handle_translate` is restored and covered through a real HTTP integration test.
- Binary responses are streamed in bounded chunks.
- A shared response writer ignores only recognized client disconnect errors.
- File open/read errors are not silently swallowed.
- Keyframe storage failures detected before headers return HTTP 503.
- `WinError 433` from an unavailable external drive remains visible as a storage problem.

## Timestamp to Frame

New endpoint:

```text
GET /api/time-to-frame?video_id=L21_V001&minutes=1&seconds=2.5
```

The service finds the nearest mapped keyframe, reads its local FPS, then estimates the requested raw frame with:

```text
nearest.frame_idx + (requested_pts_time - nearest.pts_time) * nearest.fps
```

The response includes:

- requested timestamp;
- mapping FPS;
- estimated `frame_idx`;
- nearest keyframe ID, mapped frame index and timestamp;
- nearest image URL and distance in seconds;
- an explicit manual-confirmation status.

The tool is available beside official frame inputs for:

- KIS candidates;
- Q&A review;
- each TRAKE event.

`Inspect nearest` opens the existing full-size frame inspector. `Use frame` fills the official frame field, but does not bypass manual confirmation or certify the estimate as a BTC official mapping.

## CSV Preview Save

CSV Preview now tracks the selected queued query and exposes `Save CSV`.

- Chrome/Edge: uses `showSaveFilePicker`, allowing the operator to select drive E and an exact path.
- Fallback browsers: downloads through the browser's configured download directory.
- The bytes come directly from the validated `csv_preview`; no debug or retrieval fields are added.
- KIS, Q&A and TRAKE confirmation automatically select their new CSV preview.

A browser cannot silently force a write to `E:\` for security reasons. The operator must select E in the save dialog.

## Validated CSV Editing

CSV Preview now has four guarded actions:

1. `Edit CSV` unlocks the textarea for an ACTIVE session.
2. `Apply to queue` sends the edited text to `/api/submission/query/csv`.
3. `Reset` restores the latest persisted queue version.
4. `Save CSV` downloads only the latest applied version.

The backend uses Python `csv.reader` with strict syntax handling, so quoted Q&A answers may safely contain commas and quotes. It rejects empty files, headers, invalid video IDs, negative or decimal frame IDs, invalid column counts, over 100 rows and task-specific validation failures. A successful apply updates SQLite; therefore later validation and `submission.zip` use the edited result. Save is disabled while a dirty draft has not passed validation.
