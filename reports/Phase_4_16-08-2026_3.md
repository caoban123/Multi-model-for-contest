## Current Status

## What Changed

- Added deterministic bilingual alias dictionary `object-aliases-v1.0`; normalization is rule-based and uses no LLM.
- Added normalized schema `phase4-object-store-1.0` retaining raw label, normalized label, confidence, label ID, bbox, center, area, source and schema version.
- Built an indexed SQLite store from the complete L21 frame registry.
- Stored every frame before its detections, including explicit `UNKNOWN` rows for missing/invalid object data.
- Added a manifest with content fingerprints, coverage, counts, build configuration and store size.

## Open Issues

- **OPEN:** Alias coverage is intentionally conservative; unmapped raw labels fall back to deterministic snake_case.
- **OPEN:** The 159 MB store is local/generated and must be rebuilt when source fingerprints change.
- **OPEN:** Confidence/NMS settings require development-set experiments.

## Upgrade Opportunities

- Add alias entries only from reviewed failure cases and bump the dictionary version.
- Add a manifest compatibility check when the store is opened by the service.

## Decisions Needed

- No threshold or NMS default is selected here. P4.3 must expose both as configuration.

## Risks

- Broad aliases such as `person` grouping man/woman/boy/girl improve recall but can reduce semantic specificity; raw labels remain available for evidence/debug.
- Rebuilding the SQLite file is destructive to that generated artifact, so the builder targets only the exact configured output path.
