## Upgrade Opportunities

- Use BM25 as the low-cost first-stage retriever for exact terms and dates.
- Keep SQLite read-only per request and reuse the long-running UI process.
- Add field weighting only after source-level ablation exposes a clear need.
- Preserve the portable corpus/index checksum link for later L22+ incremental builds.

## Decisions Recorded

- Use built-in SQLite FTS5 instead of adding a BM25 package.
- Use Unicode `remove_diacritics 2` and deterministic accent folding.
- Convert SQLite's lower-is-better `bm25()` value to a higher-is-better raw score at the interface boundary.
- Keep BM25 opt-in until reviewed ablation data exists.

## Risks

- OR-based lexical matching can over-rank documents sharing many generic query words.
- Query expansion must remain deterministic and narrowly scoped to avoid accidental matches.
- Technical fixture quality is not representative of unseen contest queries.
- Missing OCR and partial ASR remain the main data constraints.
