## Upgrade Opportunities

- Cache the loaded BGE encoder in the long-running UI process to avoid the 12-second cold start per process.
- Add batch query encoding if Agent planning emits multiple retrieval variants.
- Consider an approximate FAISS index only after corpus growth makes exact search latency material.
- Compare metadata-only BGE against BM25 before allowing object-heavy corpus results into broad fusion.

## Decisions Recorded

- Use `BAAI/bge-m3` for multilingual Vietnamese/English semantic retrieval.
- Use exact FAISS inner-product search for L21 because 8,322 vectors are small enough.
- Keep BGE modular and opt-in; do not promote it from the current CLIP baseline based on smoke fixtures.
- Keep unchunked document boundaries while every source document is within the model limit.

## Risks

- CPU index rebuild takes approximately 15.6 minutes for the current corpus.
- Windows cache duplication consumes substantial disk space.
- Dense retrieval can blur exact identifiers and dates.
- Current quality evidence is technical, not a contest-representative judged set.
- Partial ASR and empty OCR coverage constrain all text retrievers equally.
