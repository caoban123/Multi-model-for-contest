## Problem

Per-query CLIP lanes improved recall for long narratives, but they treated each visual event independently. A video could rank strongly because it contained the described moments in the wrong order. Operators also could not see which timestamps formed a plausible event chain.

## Implementation

- Added bounded temporal alignment over raw `clip:qN` frame hits.
- Treat Q1 as the broad scene prompt when at least three lanes exist; align concrete Q2-Q6 events.
- Keep at most six hits per event/video.
- Use dynamic programming to find a non-decreasing timestamp chain.
- Require at least two matched events.
- Return matched-event count, total event count, coverage, time span, compactness, rank score and exact per-event frame evidence.
- Preserve the first three video-level RRF leaders.
- Inject at most two Sequence candidates, then continue the existing per-lane round-robin rescue.
- Attach the selected chain to candidate provenance.
- Add a `Sequence` lane and `SEQ matched/total - span` chip in `/submission`.

## Safety Boundary

- No index or data rebuild is required.
- CLIP remains the default visual retriever.
- RRF remains the consensus baseline.
- Temporal evidence is advisory and affects only the bounded review ordering.
- The server still requires operator review and an official frame ID before submission confirmation.
- Coincidental ordered events may occur in montage/news videos; no automatic score-level promotion is allowed without labelled evaluation.

## Operator Workflow

1. Enter a long narrative query in `/submission` and run Agent search.
2. Inspect the generated Q1-Q6 CLIP prompts.
3. Select `Sequence` to show candidates with ordered event evidence.
4. Hover the `SEQ` chip to inspect the event timestamps.
5. Compare individual Q lanes when one event is visually distinctive.
6. Use `Refine in video`, nearby frames and video playback to locate the exact answer frame.
7. Confirm the official frame ID manually.
