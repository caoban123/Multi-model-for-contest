## Confirmed Findings

### Q&A

- The workflow already supports typed evidence, local answering, optional Gemini VLM, review and submission import.
- The benchmark contains four unlabelled templates, so current answer/retrieval quality is unavailable.
- Evidence is capped globally per modality and is not hard-grouped to one active video.
- Submission import selects the first selected frame-level evidence, creating a cross-video risk when the user selected evidence from multiple videos.
- Candidate metadata is not guaranteed to be proactively enriched for every Q&A candidate.
- The submission UI shows evidence rows but does not provide KIS-level candidate cards, metadata, matched-frame exploration or candidate comparison.
- The latest full-data audit reported OCR 0 documents and ASR coverage for 2/873 videos.

### TRAKE

- TRAKE V2 already contains adaptive retrieval, temporal feasibility, candidate windows, dense refinement, DANTE alignment, context/linkage scoring and an ablation framework.
- The development and holdout datasets remain unlabelled templates, so there is no defensible quality claim.
- Backend operations for plan updates, candidate replacement, event locking and refinement are not exposed in the `/submission` workflow.
- VLM verification is disabled and must remain experimental until OFF/ON benchmark evidence exists.

## Decision

Proceed in dependency order:

1. Data capability audit and labelled development/holdout sets.
2. Shared candidate contract, deterministic metadata enrichment and same-video Q&A evidence gate.
3. Q&A feature parity and TRAKE repair controls in `/submission`.
4. Measured Q&A two-stage retrieval and TRAKE candidate/alignment improvements.
5. Optional bounded VLM experiments.
6. Frozen holdout evaluation and promote/rollback decision.
