## What Changed

- Introduced a centralized Sky Blue design system with surface, border, text, semantic, spacing, radius and shadow tokens.
- Added a compact product header with dataset/health badges instead of a long metadata sentence.
- Reorganized the existing controls into one search workspace with explicit hierarchy.
- Styled Visual/Metadata as primary channel tabs and Video/Frame Ranking as a lighter segmented control to reflect different semantics.
- Kept Translate secondary and made Search the dominant CTA, including lightweight loading labels.
- Converted retrieval statistics into compact status pills.
- Redesigned result cards for faster scanning: image, rank, video ID, score, two-line title, compact facts and secondary actions.
- Replaced the generic missing-image block with an intentional illustrated placeholder that preserves keyframe context.
- Styled matched frames and timeline neighbors consistently with the new design system without changing their logic.
- Reduced Pins/History visual weight and added visible item counts.
- Added useful initial, empty-result and loading states.
- Added responsive layouts for wide desktop, medium and small viewports.
- Improved labels, tab semantics, selected state, focus visibility, live status output and reduced-motion handling.

## Design System

The stylesheet now centralizes:

```text
Page/soft/selected backgrounds
Primary blue scale
White and secondary surfaces
Default and strong borders
Primary/secondary/muted text
Success/warning/danger states
4/8/12/16/24/32 spacing scale
Small/medium/large radii
Subtle card/panel shadows
```

Blue is reserved for the primary action, selected channel, rank and important retrieval states. Body text remains slate for readability, while utility actions stay neutral.

## Upgrade Opportunities

- Add a compact skeleton only if real network latency makes the current button/status loading feedback insufficient.
- Add an optional collapsed filter/debug drawer when more retrieval controls are introduced in later phases.
- Add visual regression snapshots to CI if a browser test environment becomes part of the repository.
- Improve thumbnail coverage after the complete approved keyframe dataset is available; the UI already supports mixed image/no-image results.

## Risks

- Limited local image coverage can make a healthy UI appear data-incomplete; the placeholder deliberately distinguishes this from a broken image.
- Increasing Candidate Pool produces more cards/matched-frame content and therefore longer pages; responsive behavior is verified, but extremely large interactive result sets may later need pagination or virtualization.
- The translation badge reports backend configuration, not a continuous external-provider availability guarantee.
- Future changes to existing IDs/classes used by the static tests or JavaScript selectors should be coordinated across all three frontend files.
