## Milestone Result

The current milestone is implementation-complete and regression-tested. CLIP remains the visual baseline, while BGE, BM25 and structured evidence are selected by query intent. The `/submission` workspace now supports direct KIS, Q&A and TRAKE review instead of requiring users to transfer workflow IDs manually.

## Retrieval Routing

The hybrid plan contract is now `hybrid-query-plan-v3`:

| Intent | Primary route | Fusion |
|---|---|---|
| Visible scene, action, object or color | CLIP | None unless structured support is present |
| Semantic spoken/text content | BGE | None |
| Exact text, entity, date, number or metadata | BM25 | None |
| Query requiring multiple evidence sources | Relevant route combination | RRF |

Gemini remains optional. Its raw JSON is preserved for inspection, but retriever routes are normalized by deterministic local intent guardrails. This prevents an over-broad Gemini response from enabling CLIP, BGE and BM25 for every query.

## Structured Constraint Reranking

Explicit object, attribute, OCR, ASR and metadata suggestions can support Agent ranking. The integration is modular and fail-open:

- The primary retriever runs first.
- Structured channels inspect a bounded candidate pool.
- RRF is applied only when structured evidence has at least one supporting hit.
- Zero support or a channel failure preserves the primary ranking.
- The full `/api/structured-search` workflow remains separately available.

### Object performance issue

The 4.59 GB object SQLite contains 17,732,100 detections. A `person` query that enumerated the whole frames table exceeded 180 seconds. Candidate-scoped SQLite remained about 40 seconds because random index access on the external drive was expensive.

Resolution:

- Candidate-scoped object validation reads only the source JSON files for proposed frames.
- It uses the same alias normalization, confidence threshold, NMS, position and count checks.
- SQLite remains the whole-store audit/search source.
- Measured Top-120 candidate scan: 0.137 seconds cold and 0.080 seconds warm.

## Submission UI

The `/submission` workspace now includes:

- Full-size image dialog for KIS candidates, Q&A evidence and TRAKE events.
- Previous/next keyboard navigation in a neighborhood sequence.
- Neighborhood radii 3, 6, 12 and 20.
- Current-frame highlight, keyframe/frame/timestamp labels and copy-details action.
- Responsive desktop/mobile layouts with no horizontal overflow in smoke screenshots.
- Gemini raw text, parsed JSON and validated system plan for Agent queries.

### Q&A direct flow

`Prepare evidence -> select source evidence -> optional Gemini/evidence-first draft -> edit/review -> enter official frame ID -> add to queue`.

Confirmation requires at least one selected frame-level evidence item. Gemini receives only selected evidence and related images through the existing Phase 7 answerer.

### TRAKE direct flow

`Plan events -> retrieve -> temporal align -> select chain -> inspect each event -> enter one official frame ID per event -> review -> add to queue`.

TRAKE remains an L21-only contract. Hybrid event retrieval is now explicitly restricted to `request.group`, preventing full L21-L30 UI configuration from leaking non-L21 candidates into a TRAKE chain. `NO_FEASIBLE_VIDEO` remains an expected fail-closed result.

## Known Limitations

- OCR contributes zero usable documents.
- ASR covers only 2/873 videos.
- Full-data Hybrid has not passed a sufficiently broad quality benchmark, so it is not promoted globally.
- TRAKE quality still needs manual development/holdout labels.
- Retrieval `keyframe_id` and `frame_idx` remain diagnostics. Official frame IDs must be manually verified or supplied by a future BTC-certified mapping.
- External drive availability can intermittently raise Windows `WinError 433`; the documented startup command uses physical E-drive paths for large artifacts and metadata.

### External-drive regression found during final validation

The full suite initially reported 2 failures in the standalone benchmark review HTML renderer because `Path.resolve()` dereferenced the keyframe junction while drive E was temporarily unavailable. The renderer now constructs lexical absolute/relative paths without touching the target device. The focused renderer tests and the full 354-test suite pass after the fix.

## Decision

Promote intent-specific routing and the direct submission review UI as the current Phase 9 implementation. Do not promote always-on three-way Hybrid Retrieval. Keep every official frame mapping behind the manual confirmation gate.
