# Phase 8 — TRAKE two-stage contract correction

The implementation now follows the TRAKE definition rather than treating the
task as a gallery of independently retrieved event frames.

1. **Retrieval:** rank candidate videos by complete required-event coverage and
   a feasible same-video monotonic temporal witness; select exactly one video.
2. **Alignment:** construct/refine keyframes only inside that retrieved video,
   retain exactly one temporally valid chain, and expose its answer as
   `<video_id>, <frame_id_1>, ..., <frame_id_N>`.

The workspace presents the stage-1 video separately from the stage-2 TRAKE
answer. Dense-frame `frame_idx`, rather than a source retrieval keyframe id,
is shown and emitted as the answer frame id. If no one video covers the event
sequence, the system returns no answer rather than combining candidates from
different videos.

Live local verification after server restart:

```text
query:  a person walks in → opens a door → sits down
answer: L21_V008, 6085, 6297, 6659
```

This validates retrieval/alignment invariants only. Semantic action correctness
still requires ground-truth intervals or an action-capable verifier; the UI
continues to require manual semantic review before confirmation.
