## Current Status

The Gemini translation path is still optional and controlled by environment variables. This revision improves troubleshooting after a real UI run returned `HTTP Error 400: Bad Request`.

## What Changed

- Updated Gemini default model from `gemini-2.0-flash` to `gemini-3.5-flash`.
- Gemini 400/401/403 responses now include the API error body in the UI/server message.
- README now recommends `gemini-3.5-flash` and notes that contributors can try `gemini-3.6-flash` if their key supports it.

## Why

The previous error message only showed:

```text
Gemini translation API request failed: HTTP Error 400: Bad Request
```

That was not actionable. The client now reads the response body from Gemini and should report details such as invalid API key, unavailable model, or malformed request.
