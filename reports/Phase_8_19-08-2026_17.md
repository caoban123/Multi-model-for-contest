# Phase 8 TRAKE V2 — P8.V2.13 Performance + P8.V2.14 Failure Diagnostics

## P8.V2.13 — measured optimization

- Kept the validated 7,800 × 512 NumPy index; no ANN/vector database migration was made.
- Existing startup maps (`refs_by_video`, sorted temporal refs, asset registry) remain preloaded outside DP loops.
- Visual query text/variants are batch encoded and searched by one matrix multiplication.
- Added a bounded, fingerprint-partitioned in-memory text-embedding cache (2,048 entries by config).
- Dense decoded candidates already use bounded on-disk cache keys containing video/model/config/index fingerprints.
- Split persisted timings into planner, embedding, retrieval, fusion, temporal filter, window build, dense decode, alignment, rerank, and total.
- Added `tools/phase8_profile.py`; it opens SQLite read-only and emits per-stage p50/p95 for all and warm sessions without requiring quality labels.

Measured evidence:

- Existing persisted historical Phase-8 sessions (4 total; not full V2): total p50 `219.1305 ms`, p95 `359.091 ms`; warm sessions (3): p50 `145.02 ms`, p95 `359.091 ms`.
- Controlled in-memory V2 algorithm fixture, 30 runs, no model encoding/video decode: total p50 `4.187 ms`, p95 `6.778 ms`; planner `2.703/5.493 ms`, alignment `0.410/0.656 ms`, rerank `0.431/1.321 ms` (p50/p95).
- Earlier 3,000-candidate DANTE sanity: `233.016 ms` for Top-3 with beam 20.

The controlled V2 number excludes real CLIP encoding, structured stores, and dense video seek, so it is not a warm L21 end-to-end latency claim. A full V2 p50/p95 remains unavailable until persisted real V2 sessions are collected.

## P8.V2.14 — debuggable queries

Every persisted V2 query now exposes:

- planner version, global context, raw/visual event text, variants, selected modalities, confidence, and warnings;
- Top-K per event, top score, margin, distinctiveness and its components;
- candidate-video coverage;
- feasibility before/after and exact removal reasons;
- bounded candidate windows and anchor;
- dense coarse/fine status, selected windows, decoded-frame count, and the explicit absent quality claim;
- alignment paths, selected timestamps, failures, full final score breakdown, and before/after rerank IDs;
- per-stage latency.

Expected domain failures now use typed codes and persist the failure stage before raising. Tests cover `NO_CANDIDATES`; existing tests cover `NO_FEASIBLE_VIDEO`, and the workflow also exposes `NO_CANDIDATE_WINDOW`.

No OCR writer, source video, source keyframe, store schema, external service, or model download was touched by these optimizations.
