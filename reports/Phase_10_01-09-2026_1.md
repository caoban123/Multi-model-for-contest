## Current Status

**VERIFIED** for technical implementation and runtime integration. **IMPLEMENTED_UNVERIFIED** for retrieval-quality improvement because no labelled dense-frame benchmark has been completed.

KIS and Q&A can now optionally decode bounded source-video neighborhoods after Stage-A retrieval, score frames with the existing CLIP model, refine around strong coarse anchors, cache selected frames and present them for manual review. TRAKE's existing decoded refinement now resolves videos through the same registry-owned path logic. Baseline keyframe behavior remains available as fallback.

## What Changed

- Added `DenseFrameLocalizer` with bounded coarse-to-fine sampling, CLIP scoring, temporal diversity and deterministic cache fingerprints.
- Added source-video resolution through the data registry so videos behind the `D:/AIC1/data` junction may safely resolve to the external SSD.
- Added exact decoded `frame_idx`, `pts_time`, seek error and source/mapping status to candidate rows.
- Added graceful fallback for missing seed timestamps, FPS, source video, video stat, decoder, scorer and cache writes.
- Fixed OpenCV BGR-to-RGB negative-stride arrays by copying them before PyTorch/CLIP ingestion and image writes.
- Added decoded-video refinement to KIS candidate review and Q&A Stage B without changing Stage-A video rank.
- Connected TRAKE dense components to the registry video resolver.
- Added a Deep frame search option, decoded-frame badges and a contact-sheet review flow in `/submission`.
- Encoded Windows keyframe paths before placing them in image URLs; verified the endpoint serves the cached JPEG.
- Enabled dense localization explicitly in the competition profile with an external SSD cache path.

- L21-L30 source videos remain external/local data and are never copied into Git.

## Upgrade Opportunities

- Add a competition prewarm command for common seed windows.
- Add optional GPU device diagnostics and decode/scoring latency telemetry to the UI.
- Use labelled failure cases to tune radius, coarse FPS, fine FPS and temporal gap by task instead of globally.
- Consider an offline full-frame embedding index only after storage, build time and measured accuracy justify it.

## Decisions Needed

- Decide the organizer's official frame-numbering convention before allowing decoded `frame_idx` to bypass manual confirmation.
- Decide whether dense search should remain a checked UI option or become mandatory only after labelled comparison.

## Risks

- A larger frame search window can increase latency without improving relevance.
- CLIP can still miss small text, fine-grained actions or answer-specific details; OCR/ASR/VLM evidence remains necessary.
- External SSD disconnects can make source video unavailable. The service now falls back instead of failing the request.
- Gemini remains advisory and network-dependent; local retrieval and manual review must remain usable without it.
