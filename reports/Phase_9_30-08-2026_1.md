## Problem Addressed

Global text retrieval can identify the correct video while returning weak or video-level evidence instead of the exact answer frame. Global OCR can also be distracted by repeated semantically similar text in unrelated videos. The new workflow keeps broad candidate discovery separate from frame localization:

1. Search globally to obtain candidate videos.
2. Let the operator choose a candidate video.
3. Search only inside that video, optionally around a seed frame.
4. Fuse frame-level CLIP, BGE OCR/ASR and BM25 OCR/ASR ranks with RRF.
5. Review the resulting frames, inspect neighboring keyframes and explicitly choose the frame used for submission.

The workflow does not silently overwrite the verified official frame ID.

## Operational Notes

- CLIP remains the visual default. BGE and BM25 remain modular and opt-in.
- RRF is used only when the query plan enables multiple channels.
- OCR/ASR matches are supporting evidence, not an automatic final answer.
- The currently running server uses the local planner because no Gemini API key was supplied to that process.
- The first query after server start is slower because model weights are loaded lazily.

## Known Limitations

- ASR coverage is only 2/873 videos, so speech-heavy retrieval remains degraded outside those videos.
- OCR may contain recognition errors and requires visual confirmation.
- Candidate-local refinement improves frame recall but does not prove that rank 1 is the official answer frame.
- A frozen, human-judged CLIP/BGE/BM25/RRF ablation is still required before changing defaults.
