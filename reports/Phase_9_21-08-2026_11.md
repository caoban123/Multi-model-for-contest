## Milestone Result

The `/submission` workspace now presents every queued query and every generated CSV as independent review items. It no longer has a single shared CSV preview that gets replaced when another query is confirmed.

## Queue Behavior

- The backend did not contain a two-query limit. Its deterministic identity is `(session_id, query_id)`.
- A new Query ID appends another item to the current ACTIVE session.
- Confirming the same Query ID intentionally updates that existing item instead of creating a duplicate.
- The queue count reflects all distinct Query IDs.
- The desktop queue has its own vertical scroll region, so a long contest session does not stretch the entire page.
- Narrow layouts return to normal document flow to avoid nested scrolling on mobile.

## Per-query CSV Files

The former single CSV Preview is replaced by a collapsible CSV Files list. Every queued query has its own:

- generated filename and task/row summary;
- read-only applied content;
- Edit action;
- task-aware Apply action through `POST /api/submission/query/csv`;
- Reset action to restore the persisted SQLite version;
- Save action for downloading only that CSV.

Editor state is keyed by Query ID. An unapplied draft survives unrelated queue renders, and applying one file does not change another file. Validate and Done are disabled whenever any file has a dirty draft. Save is disabled only for the dirty file until its draft passes server validation and is persisted.

Chrome/Edge uses the native save picker for each file. Other browsers use their configured download behavior. Browser security still requires the operator to choose drive E manually.
