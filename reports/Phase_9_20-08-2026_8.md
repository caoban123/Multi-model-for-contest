## Official Contract Implemented

- KIS row: exactly `video_id,frame_id`.
- Q&A row: exactly `video_id,frame_id,answer`.
- TRAKE row: exactly `video_id` plus N event frame IDs.
- Query filename suffix must match task.
- Each query contains 1-100 predictions.
- Video ID matches `LNN_VNNN` and excludes `.mp4`.
- Frame IDs are non-negative integers.
- Q&A answer is non-empty and at most 100 characters.
- TRAKE event count is exact; non-increasing frame IDs produce a warning requiring timestamp review.
- ZIP contains CSV files only under `submission/`.

## Decisions Recorded

- H8 is `VERIFIED_GUARDED`, not `DONE`.
- Retrieval diagnostics may be stored in SQLite sidecar source JSON but never enter official writers.
- Internal Q&A `frame_id` is treated as keyframe-level evidence and is never trusted as official frame ID.
- Internal TRAKE `frame_idx` is never copied automatically into official output.
- Warnings do not block ZIP unless they indicate an ERROR; unresolved manual review remains visible.
- DONE sessions are read-only through service guards.
- No upload to BTC is automated.

## Risks

- A user can manually enter the wrong official frame ID; the guard proves intent/source, not semantic correctness.
- Browser layout has static and syntax validation but no screenshot-based acceptance.
- Importing the wrong Q&A/TRAKE review ID can select a valid but unintended reviewed record.
- Submission attempt limits are operational policy and are not yet represented in SQLite.
- Current H6 quality evidence is insufficient to promote Hybrid as the default KIS retrieval route.
