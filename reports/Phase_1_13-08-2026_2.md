## Current Status

**DONE — Phase 1 data registry and baseline retrieval; L21 KIS path integration-verified.**

The delivered baseline accepts a natural-language query, encodes it with local CLIP ViT-B/32, searches BTC-provided image-feature vectors using NumPy cosine similarity, and returns `video_id`, `keyframe_id`, `frame_idx`, and timestamp through the keyframe mapping. The standard Phase-1 data layout spans L21-L30; the complete runnable KIS evidence recorded in this report is L21.

This status does not claim a score from an official AIC ground-truth set. Metadata search and object fusion remain experimental independent work; they are not part of the default KIS path.

## What Changed

- Rebuilt the canonical local registry and persistent L21 NumPy index after `map-keyframes` was provided.
- Changed Phase-1 preflight to accept `--groups` (default `L21`) so each contributor can validate the data subset installed on their own machine.
- Fixed preflight keyframe-image counting: it now reports the real count rather than collapsing repeated counts through a `Counter` key.
- Declared local keyframe images as optional visual aids. Their partial coverage is now a `WARNING`, not a KIS blocker; feature/mapping presence, row consistency, and 512-dimensional features remain blocking checks.
- Updated README commands to build/search all 7,800 L21 vectors without `--require-keyframes`, and removed machine-specific data/model assertions.
