## Data Status

- Queries operate on 6,212 `AVAILABLE` frames and report 1,588 `UNKNOWN` frames separately.
- An available frame that fails a predicate is `NO_MATCH`; a missing frame remains `UNKNOWN`.
- `min_confidence` defaults to 0.3 only as an exposed runtime value, not a final benchmark decision.
- `nms_iou_threshold` defaults to 0.5 and is configurable.

## Benchmark / Metrics

- Real Vietnamese query `điện thoại` normalized to `phone` and returned `L21_V028/17` first at confidence 0.997397.
- Real query `person >= 2` on the left at confidence ≥0.5 returned `L21_V011/256` first with two post-NMS detections.
- Experimental phone/hand proximity produced evidence-bearing results; these are samples, not relevance claims.
- Retrieval-quality and threshold-quality metrics remain unavailable pending P4.9 judgement/ablation.

## Open Issues

- **OPEN:** NMS and confidence defaults are provisional until development-set analysis.
- **OPEN:** Position uses detection center, so a large box crossing all regions belongs to exactly the region containing its center.
- **OPEN:** Phone/hand proximity is a weak heuristic and must remain experimental/soft.

## Upgrade Opportunities

- Add reviewed per-label confidence calibration in a later phase if benchmark evidence supports it.

## Decisions Needed

- Keep interaction disabled unless explicitly requested. Do not call it a holding detector.

## Risks

- `<=` count predicates intentionally match available frames with zero qualifying detections; callers must not interpret the resulting zero object score as a fabricated relevance score.
- Dense generic detections can still create false positives after NMS.
