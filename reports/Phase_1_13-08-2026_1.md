## What Changed

- Added `requirements-test.txt` (`numpy`, `pytest`) and `requirements-phase1.txt` (test profile plus `torch`, `transformers`).
- Added `configs/phase1_data_manifest.json` with previous-report expectations for L21-L30. These are expected values, not measurements made in this run.
- Added `tools/check_phase1_data.py` and `src/aic_retrieval/phase1_data.py`:
  - read-only preflight reporting `OK`, `WARNING`, `MISSING`, or `INVALID`;
  - validates required directories, observed coverage, registry schema, feature/mapping validation, L21 image availability, and expected non-L21 image absence.
- Added deterministic SHA-256 provenance helpers and index metadata schema `2.0`:
  - registry, feature source, and mapping source fingerprints;
  - build timestamp, scope, vector/ref counts, dimension, dtype, model/provenance placeholders.
- Persistent index search now validates scope/freshness by default and rejects incomplete legacy provenance, wrong group, keyframe-scope mismatch, or changed sources. `--allow-stale-index` is an explicit debug-only override.
- Added an automated non-L21 fixture proving mapping fields survive while `keyframe_path` is `null`.
- Updated metadata retrieval to retain original accented tokens as well as stripped tokens. Exact original token/phrase matches outrank stripped matches; unaccented search remains supported.
- Added `benchmarks/metadata_queries.json`, explicitly marked as a CI fixture benchmark rather than official AIC ground truth, and `tools/benchmark_metadata.py`.
- Metadata benchmark records version, timestamps, query/media fingerprints, Recall@1/5/10, MRR, query-type breakdown, false positives before first relevant result, and mean/p50/p95 latency.
- KIS benchmark output now records benchmark provenance and latency summary; existing q008/q009/q010 query IDs remain intact and are tagged as location/relation/color regression classes.
- Updated README with profiles, preflight, scope, stale-index behavior, and metadata fixture benchmark commands.

## Risks

- SHA-256 source validation reads source files during persistent-index verification. It is safe and deterministic, but may be noticeably slower on a full all-group index; benchmark it before using it in an interactive long-running service.
- An old index without provenance is rejected by default. The explicit `--allow-stale-index` override is for debug only and must not be used as integration evidence.
- The metadata fixture benchmark validates tooling only; it says nothing about contest-data retrieval quality.
- Metadata results identify video-level records, not final KIS keyframes.
