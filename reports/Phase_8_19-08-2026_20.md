# Phase 8 TRAKE V2 — P8.V2.17 E2E, Hardening, and Final Handoff

## Checkpoint result

P8.V2.17 is implemented. The Phase 8 runtime now exposes the typed `trake_v2` configuration and coarse-to-fine execution path while retaining an explicit legacy path for compatibility and controlled comparisons.

The completed V2 path is:

1. rule-first planner with manual overrides and query variants;
2. batched high-recall per-event retrieval with source-aware RRF and adaptive Top-K;
3. distinctiveness-based anchor selection;
4. hard-constraint temporal feasibility filtering;
5. anchor-aware bounded candidate windows;
6. DANTE-inspired coarse ordered alignment;
7. bounded dense video-seek expansion with PTS/mapping provenance and fingerprinted cache;
8. DANTE-inspired fine ordered alignment;
9. explicit multimodal, context, linkage, coverage, and temporal reranking;
10. invariant validation, append-only human review, and confirmed-only export.

The implementation is inspired by the requested concepts (Vortex-style rank fusion, K-pointer-style feasibility, MADTempo-style temporal windows, DANTE-style dynamic programming, and continuity/linkage scoring). It does not claim an exact reproduction of any paper or external system.

## Hardening completed

- TRAKE store version is now `phase8-trake-store-v2` with readable V1/V2 compatibility and a recorded, non-destructive V1 → V2 migration.
- API errors use stable HTTP/domain semantics: missing session `404`, malformed request `400`, domain failure `422`, unexpected failure `500` with a generic client message.
- Unexpected tracebacks are logged server-side and are not returned to the browser.
- A missing offline CLIP model is converted to the typed `RETRIEVAL_UNAVAILABLE`/`RETRIEVAL` result instead of an unstructured 500.
- `/api/trake/health` exposes the active algorithm, config fingerprint, and actual VLM state.
- The UI safely escapes dynamic HTML and displays V2 planner, retrieval, alignment, score-breakdown, provenance, and stage-latency diagnostics without a broad visual redesign.
- VLM remains disabled. No provider call or model download was performed.

## E2E evidence

`tests/test_trake_e2e_v2.py` executes a controlled complete route:

`plan → search → temporal feasibility → candidate windows → coarse dense expansion → DANTE coarse → fine dense expansion → DANTE fine → final rerank → invariant validation → review → export → store reopen`

It verifies ordered same-video output, dense video-seek mapping, requested/decoded PTS provenance, estimated frame-index marking, final rerank components, confirmed-only export, and persisted V2 diagnostics.

Browser verification against the real local server confirmed:

- the planner produced two ordered events for `a person enters then sits down`;
- the event editor, query variants/modalities, V2 debug JSON, and planner latency rendered correctly;
- the active health result was `algorithm=trake_v2`, `vlm_enabled=false`, config fingerprint `527e20a54cb0cccc8793494a82e1edd6bbb472513acdc9c2988f197923733d18`;
- with `--clip-local-files-only` and no configured CLIP model in the machine cache, Retrieve returned the sanitized UI message `RETRIEVAL_UNAVAILABLE: local text encoder is unavailable; preload the configured model or allow its download`.

The live browser run therefore verifies the real UI/API success path through planning and the controlled offline failure path through retrieval. It does not provide live retrieval-quality evidence because the required CLIP model is absent locally. The controlled fixture E2E verifies the complete algorithmic route without downloading a model or fabricating benchmark labels.
